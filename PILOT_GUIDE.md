# Literacy Quest — Family pilot guide

## Purpose and current status

This is a small usability try-out, not a reading assessment or a study of learning effectiveness. The software and content were checked during development. **No student or parent pilot results have been collected yet.**

Suggested first group: 3–5 families using their usual device, including one Kindergarten/Grade 1 learner and one Grade 4/5 learner if available. Participation is optional. A grown-up should sit with each child. Do not send names, contact details, or a full learning backup as feedback.

## Before the session

1. The site owner replaces the GitHub Pages `index.html` with the updated file. Use the same site address to retain the browser’s existing learning records.
2. A returning family downloads its learning backup first through the learner menu → Learners & backups.
3. Set aside 15–20 minutes to explore navigation. A full Grade 4/5 lesson may take longer; completing it is not necessary.
4. Use a separate nickname profile for a test learner. Do not change another child’s writing.

## Opening script

“We are trying the website, not testing you. Please tell us what you think a button will do. If something is confusing, that helps us improve it. You can ask for help or stop whenever you want.”

## Tasks to observe

| Task | What to notice |
| --- | --- |
| Choose a grade on My day | Is the chosen grade clear? Can the family tell Grades 1 and 2 share readings? |
| Open the suggested lesson | Is the recommendation’s reason understandable? |
| Try word practice and a hint | Are answer feedback and Keep going understandable? |
| Read or listen | Is text readable? If audio is unavailable, can the family continue by reading together? |
| Enter an idea, choose Save & back, reload | Does Resume this lesson return to the saved activity and writing? |
| Open My creations | Can the family find and reopen saved writing? |
| Open Learners & backups | Can the grown-up locate and download a backup? Keep it private. |

For Kindergarten, adult reading/typing is expected. Distinguish ordinary learning support from help needed because the interface is confusing. Observe a real pause; do not label a child’s reading difficulty as a navigation defect.

## Record observations

After the learning tasks, open **For grown-ups → Try it together · family feedback sheet**. Select Independently / With help / Could not finish / Not tried. Add brief observations and download the `.txt` report before leaving that section. The sheet is temporary, and no feedback is automatically transmitted.

Ask: What felt easiest? Where did you stop or need help? What would make the next visit easier? Would you know what to do tomorrow?

The site owner can collect the downloaded text reports through an agreed channel. Do not ask families to share a learning backup for usability feedback. The app has no automatic analytics or server-side feedback collection.

## Triage after the pilot

- **Fix before wider use:** missing saved work, wrong learner’s records, blocked lesson flow, unusable controls.
- **Fix next:** the same unclear direction or navigation problem appears in two or more sessions.
- **Consider later:** individual visual preferences or requests for more content.

Suggested readiness criteria for the next small release: no unresolved save/resume or learner-isolation defect; all participating families can find their saved work after normal orientation; recurring navigation blockers addressed. These are project targets, not research findings.
